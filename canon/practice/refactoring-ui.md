# Checking visual hierarchy on a task screen

- **Start with the work.** Sketch the essential actions for one scenario before choosing a page shell. On a returns screen, put the item and refund decision in view first, then decide where to show the order history and help.
- **Compare emphasis in context.** Use spacing, weight and contrast to group related content and draw attention to the next action. Read the screen at a glance, then check the document structure and control names separately with semantic inspection. Give field labels and interactive states persistent, perceivable cues.
- **Use the product's token roles.** Apply existing type, spacing and color roles where they fit. If a recurring need has no matching token, document the proposed role and show it across representative screens. Adjust text measure and layout against real content at supported widths.
- **Check color pairs and layers.** Test foregrounds against their actual backgrounds in applicable modes and states. Give statuses a text or other perceivable cue in addition to color. Check that borders, shadows or surface changes clarify relationships and that keyboard focus stays visible.
- **Try difficult content before polishing.** Compare long titles, missing images, and empty or crowded lists. Test the crop and text contrast of image-backed content across breakpoints. Use the empty state to explain what is missing and give the relevant next action.

Source: Adam Wathan and Steve Schoger, [*Refactoring UI*](https://www.refactoringui.com/), 2018. See the [visual systems rules](../visual-systems.md) for related checks.
