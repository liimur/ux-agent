# Reviewing a form from entry to confirmation

- **Account for each field.** Tie it to a decision or action in the flow. For a workshop booking, ask for accessibility requirements only where staff can act on them. Explain why sensitive or unexpected information is requested and distinguish optional inputs consistently.
- **Trace reading and input order.** Group related fields and use persistent labels with programmatic associations. Try a single column as an initial layout, then test narrow screens and keyboard order. Choose suitable input modes and autocomplete tokens where applicable.
- **Make conditional questions predictable.** If someone asks for an invoice, reveal the billing fields beside that choice. Keep defaults visible and editable. Accept harmless variations such as spaces in a phone number. Ask for clarification when values could be interpreted in more than one way.
- **Exercise failure and recovery.** Try a missing value, a server rejection and a slow response. Say which field needs attention, explain how to correct it where possible, and keep valid entries where appropriate. Link a summary to the relevant fields if errors span the form. Verify that feedback reaches keyboard and screen reader users.
- **Confirm the outcome.** Describe what was submitted and what happens next. Decide whether cancellation, editing or a draft saves meaningful work. Prevent accidental duplicate submission and verify recovery after a timeout.

Sources: Luke Wroblewski, [*Web Form Design: Filling in the Blanks*](https://rosenfeldmedia.com/books/web-form-design/), 2008, and the author's [2008 form design slides](https://static.lukew.com/webforms_lukew.pdf). Consult the [WCAG criteria](https://www.w3.org/TR/WCAG22/) for accessibility requirements.
