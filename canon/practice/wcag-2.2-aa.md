# Accessibility review prompts for web flows

Use these checks to collect evidence for common web flows. For a Level AA conformance assessment, use the complete W3C criteria and conformance requirements, including their conditions and exceptions.

| Scenario | What to exercise | Related WCAG 2.2 criteria |
| --- | --- | --- |
| Read and navigate | Inspect headings, labels and link destinations. Follow the task in document order with assistive technology. Check whether a user can skip repeated navigation. | 1.3.1, 1.3.2, 2.4.1, 2.4.4, 2.4.6 |
| Read at different sizes | Check contrast on actual backgrounds, including meaningful controls and graphics. Try zoom and user-defined text spacing. Check that information conveyed through color still makes sense without the color. | 1.4.1, 1.4.3, 1.4.4, 1.4.10–1.4.12 |
| Operate a component | Complete the task with the keyboard. Observe the focus indicator and whether sticky content covers the focused control. For drag actions, exercise a pointer method that works without dragging as well as the keyboard path. Check target dimensions and spacing. | 2.1.1, 2.1.2, 2.4.3, 2.4.7, 2.4.11, 2.5.7, 2.5.8 |
| Submit or recover | Trigger an input error and inspect the available instructions, field associations and spoken feedback. Check whether already supplied information is available for reuse where the criterion applies. Inspect controls for accessible names and state. | 3.3.1–3.3.4, 3.3.7, 4.1.2, 4.1.3 |
| Sign in or use media | Try the sign-in alternatives and assistance offered, check language information, and inspect captions, descriptions or text alternatives for the applicable media. | 1.1.1, 1.2.1–1.2.5, 3.1.1, 3.1.2, 3.3.8 |

For each finding, record the screen, steps, actual behavior and criterion. Mark checks that need a working build or assistive technology as unverified until exercised.

Source: W3C, [*Web Content Accessibility Guidelines (WCAG) 2.2*](https://www.w3.org/TR/WCAG22/).
