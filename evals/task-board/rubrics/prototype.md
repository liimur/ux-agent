# Interactive prototype rubric

Command: `ux-design`. Inputs: `input/brief.md`, `input/system-source.md`. Request a working HTML prototype.

- [ ] The prototype runs from the stated path and implements create with title and owner, display on the board, mark done, and an error with recovery.
- [ ] A reviewer can complete the scenario with the keyboard alone; focus is visible and not lost after actions.
- [ ] Inputs have persistent labels and errors are programmatically associated with their fields.
- [ ] The prototype specification lists implemented, simulated and missing behavior, and the checks actually run with tool and viewport.
- [ ] Uses supplied tokens where they apply and marks additions (for example focus color) as proposals; does not claim WCAG conformance.
