# Project: Доска задач (example)

This is the [project template](../../templates/PROJECT.md) filled in for the fictional task board used in the [evaluations](../../evals/README.md). The original customer brief is [evals/task-board/input/brief.md](../../evals/task-board/input/brief.md); [sample outputs](output/README.md) show what the commands produce from it.

- Owner / decision maker: the customer's team lead (fictional).
- Product and problem: an internal web board so a small team can create tasks and see who owns each one.
- Users, tasks and context: team members create a task with a title and an owner, find it on the board and mark it done. They work on desktop and sometimes on a phone.
- Desired outcomes and measures: before development, check with the team that the concept is understandable. No measures defined yet.
- Platform, devices, locales and constraints: responsive web, primarily desktop, narrow mobile viewport; Russian interface. Support keyboard access in any working prototype.
- Language for communication and user-facing artifacts: Russian.
- Evidence and source links: the customer brief only. No interviews or usage data.
- Designer interview status and project rules link: not held. For a case with rules see [evals/task-board/input/designer-rules.md](../../evals/task-board/input/designer-rules.md).
- Existing design systems and precedence: design notes, revision 1 — [system-source.md](../../evals/task-board/input/system-source.md).
- Figma file / nodes and access status: none.
- Deliverable, fidelity and scope: a flow, a low-fidelity board and task-creation view, and a short review. Empty, populated, validation-error and successful creation states. Authentication, notifications and integrations are out of scope.
- Assumptions and unanswered questions: user needs and design choices are provisional assumptions.
- Accessibility target and applicable platform guidance: WCAG 2.2 AA as the target for the eventual implementation; a static wireframe cannot establish conformance.
- Decisions, rationale and status: none yet.
- Validation planned / completed: a short formative test with team members is planned; none completed.
