# Example: Team task board

This brief is entirely fictional and intended for a local smoke exercise.

- **Problem:** A small team needs to capture and track work without losing task ownership.
- **Users and task:** Team members create a task, assign an owner and move it to done.
- **Platform:** Responsive web, primarily desktop; consider a narrow mobile viewport.
- **Deliverables:** A flow, a low-fidelity board and task-creation view, and a short review report.
- **Constraints:** No existing design system is provided. Use plain, realistic sample content. Support keyboard access in any working prototype.
- **Scope:** Include empty, populated, validation-error and successful creation states. Authentication, notifications and integrations are out of scope.
- **Evidence:** No user research is supplied. User needs and design choices are provisional assumptions.
- **Validation:** A static wireframe cannot establish interaction behavior or accessibility conformance. Record actual checks and gaps.
